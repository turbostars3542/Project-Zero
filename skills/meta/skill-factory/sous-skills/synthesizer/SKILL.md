# skill-synthesizer — procédure

## Objectif
Transformer un **dossier de recherche** en une **base de connaissances structurée**, propre de
répétitions et contradiction, prête pour `builder`.

## Quand l'utiliser
Après `researcher`, avant `builder`.

## Comment faire
1. Prendre le **dossier de recherche** (output de `researcher`).
2. **Fusionner** les informations convergentes ; éliminer les **répétitions**.
3. **Résoudre ou signaler les contradictions** : si résolvable, trancher avec justification ; sinon le **signaler**.
4. **Séparer les faits vérifiés des hypothèses** (jamais les mélanger).
5. Identifier les **pratiques recommandées** (avec leur source).
6. Construire la **synthèse structurée** : faits, pratiques, hypothèses, points à vérifier — chaque
   élément **rattaché à sa source** (traçabilité préservée).
7. **Ne pas reproduire** de contenus protégés sans droit (résumer et citer, pas copier).

## Règles
- **Traçabilité** : chaque fait/assertion conserve sa provenance.
- **Faits ≠ hypothèses** : ne jamais présenter une hypothèse comme un fait.
- **Contradiction** : résolue (justifiée) ou bien **signalée** — pas occultée.
- **Droit d'auteur** : pas de reproduction non autorisée ; synthèse + citation.
- La synthèse reste **fidèle** aux sources (ne pas inventer) ; une info non confirmée est marquée.

## Vérifier (PASS = preuve)
- La synthèse est structurée, sans répétition, faits vs hypothèses distingués, chaque point sourcé.
- Contradictions résolues OU signalées ; aucune reproduction non autorisée.
